Same flags, 0.28 dies on WSL and 0.30 starts — what the startup log reveals

A write-up of one real upgrade, kept in the repo so the diff below has a permanent home instead of living only inside a release note.

The situation

  • Laptop GPU: one RTX 4060 Laptop, 8 GB, under WSL2.
  • The two vllm serve commands differed in exactly one thing: the version (0.28.0 vs 0.30.0). Flags, model, --gpu-memory-utilization, everything else identical.
  • 0.30.0 answered /health and a completion. 0.28.0 died during engine init with:

RuntimeError: UVA is not available

Benchmark result files would not have explained this: they record the client side, and half of the run never produced a result. The explanation is in the startup log.

What the log says

Both versions pick the V2 model runner (Using V2 Model Runner). What differs is how they react to WSL2 having no pinned memory:

0.28.0 0.30.0
startup failed ready
startup.error RuntimeError: UVA is not available <absent>
uva_buffers <absent> fallback: device memory
backend.attention <absent> (init stopped) FLASH_ATTN
engine.version 0.28.0 0.30.0

0.30.0 prints one warning and carries on:

Pinned memory is not available on this platform; falling back to device memory for UVA buffers

That fallback is vllm#56908, first released in 0.30.0. So the behaviour difference is not a misconfiguration on the user's side, and not a benchmark-side effect — it is a deliberate change in the engine, visible in one log line.

53 difference(s); 14 fact(s) identical. Absent means the log did not print it, not that it was off.

Exit code 1 here means "the two logs differ", not "the tool failed". 2 would mean it could not read one of them.

Most of those only_candidate rows are honest consequences of the baseline dying early: init stopped, so it printed nothing after the failure. Reading them as "0.28 had these turned off" would be exactly the mistake servediff refuses to make — that is why the warning line is printed above the table, and why <absent> is a value rather than a blank.

What this write-up does not claim

  • It does not say UVA caused a slowdown. Here it caused a crash. The tool reports what the log printed; whether a difference costs throughput is a benchmark question.
  • It does not generalise to other GPUs. The fallback is about pinned memory being unavailable, which on a normal Linux host with a real NVIDIA driver is not the case.

Reproducing

$ pip install servediff
$ servediff demo                       # two excerpt logs shipped with the package
$ servediff capture -o before.log -- python -m vllm.entrypoints.openai.api_server --model <model> ...
$ servediff capture -o after.log  -- <the same command>
$ servediff diff before.log after.log

capture runs the server, tees its log, and snapshots the environment before startup, so the older version's log does not have to be hunted down after the fact.
